# Contracted envelopes, grants and inbox work

Read this only when the current approval explicitly adopts
[ops-dispatch v1](../../../contracts/ops-dispatch.v1.md), or when an authorized
independent wake or recorded intent started you. It adds checks; it removes none.

## Envelopes and exact grants

Independently compare the contracted envelope and each used exact grant with the
complete current approval table and unchanged revision-v2 fingerprint, then the
whole actual diff at this head. A covered supporting edit needs no new
permission request, and no old approval gains an envelope silently. Check each
supporting path's criterion, supported owned path and necessity. Check grant
repository/ticket, approval revision/fingerprint/reference, envelope identity,
grant intent/operation key, the operative `narrow-grant` rule revision/source,
source-recomputed material and complete immutable lifecycle history. Labels,
free-form comments, builder self-grants, copied digests and same-account
attribution never supply missing authority.

The [grant helper](../../launch-fleet/scripts/grants.py) checks evidence
consistency; its result cannot authenticate sources or replace your independent
scope judgment. Refuse protected policy/self-authorization, new
contracts/interfaces, dependencies, workflows, scope, live or spending changes
without their existing approval. Changed intent/evidence/ownership/purpose/rule/
approval invalidates a grant; completion/revocation/replacement ends it. A
changed head keeps valid purpose permission but requires fresh exact-head
implementation review. A grant never approves implementation, CI bypass or
merge. Daily retrospective audit is not a second synchronous review queue;
invalid grants go to revocation and the existing hold owner. Unsupported ops
effects remain disabled under OB-A1.

## Inbox work on a finite wake

Pull pending intents from the actual GitHub ticket and pull request as well as
any push notice; OB6 owns transport, not this skill. Read complete pages and
strict source/container/time bindings, current approval, operation key, current
head, destination `reviewer`, retained assignment/prior verdict and source
sequence. Ignore superseded work, deduplicate operation keys, and never pass
unresolved earlier work in the same ticket/revision. Context is not new
authority: the selected reviewer and family, own-output authentication, green
CI, 1 + 1, re-test and verified merge requirements remain. Record and read back
your checked `ack` with the same intent/key, assignment, sequence, checked head
and checks digest only after verification; another shared-account comment is
not your acknowledgement. Accepted transport is not ACK or completion. Preserve
uncertain outcomes without blind retry, record bounded results or gaps and end:
no watcher, poll or sleep. Independent wake/access/live recovery still need OB8
evidence. Do not review your own implementation or merge your own pull request.
