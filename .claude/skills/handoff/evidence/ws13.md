## SK-B and SK-C

`handoff.resume` is WS1's take-over case. Before, the page template was inline,
so every load paid for it. Now it is [page.md](../page.md), read only when
creating or updating the page; take-over reads SKILL.md alone. The update
branch is counted too, for comparison with the same before entrypoint. The
helper only runs, so its source is never loaded.

## SK-D: mechanics in `scripts/handoff.py`

| Mechanic, formerly prose | Now |
| --- | --- |
| Verify the private repository's visibility before writing; unknown stops the write | `private <owner/repo>`: `private ok`, `refused` (exit 1) or `unknown` (exit 2) |
| One snapshot line, then exactly five sections in order; "None." under an empty heading; no keys, tokens, email addresses or thread ids | `check <file>`: `page ok` or each problem by line, never echoing the match. The section list is read from page.md, its one source |
| Land on the default branch and read it back from there; a page left on a branch hands nothing off | `landed <owner/repo> <path> <file>`: compares the default branch's bytes with the checked page |

No prose copy of these procedures remains. The landing itself stays the
project's normal git and pull-request route, under its merge rules.

## SK-E: guards

No WizSkills suite covered handoff before, so no kept suite case existed to
rerun. OpenWiz's `ho-*` skills-eval cases are model evals against the pinned
WizSkills, outside WizSkills CI; they are unchanged and were not run. The
guards are visible under "Guards" in SKILL.md.

| Guard | Enforced by |
| --- | --- |
| Orchestrator only | Visible guard and independent review: no mechanical form |
| Private target only; unknown visibility stops | `test_public_target_is_refused`, `test_unknown_visibility_is_never_private`, `test_landing_on_a_public_repository_is_refused` |
| Nothing secret on the page | `test_secrets_and_thread_ids_are_refused_without_echoing_them` (mechanical subset) |
| Five sections, none empty | `test_page_shape_problems`, `test_the_documented_page_passes` |
| Landed means on the default branch | `test_landed_reads_the_default_branch_back`, `test_a_different_default_branch_page_is_not_landed`, `test_an_unreadable_read_back_is_unknown` |

Mutating six guards in the helper turned a test red each: the public refusal,
the boolean visibility check, the secret scan, the byte comparison, the empty
section check and the privacy check before read-back. The boolean mutation
first survived, so `test_unknown_visibility_is_never_private` gained a string
`"false"` and a branch-only case before the implementation commit; it still
fails on the skeleton. The [failing-first run](ws13-red.txt) is the committed
skeleton. The checklist's exact-shape rule then found that a repeated JSON key
let a second `content` or `private` value win; the
[duplicate-key red](ws13-duplicate-red.txt) was committed before the fix.
